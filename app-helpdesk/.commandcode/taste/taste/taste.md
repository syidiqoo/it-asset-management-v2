# Taste
- Berkomunikasi dalam Bahasa Indonesia dan mengharapkan balasan/penjelasan juga dalam Bahasa Indonesia. Confidence: 0.8
- Prefers reference/admin data (categories, employees, departments, packages, locations) grouped under a single "Pengaturan" (Settings) sidebar entry that expands as a dropdown/accordion, with each entity as its own sub-page/route, rather than one combined "Master Data" page. Confidence: 0.6
- Wants the page header (title + action buttons) and the search/filter bar to stay fixed/sticky while the list scrolls — explicitly asks that search and filters "tidak bisa ikut di scroll" (must not scroll away with the content). Confidence: 0.65
- Prefers large list page sizes (~100 rows per page) so the "next" pagination control only appears after scrolling through many rows, instead of short pages. Confidence: 0.6
- Prefers consistent, identically-behaving search/filter + pagination UX across comparable list pages (e.g., wants the SIM Card feature to have "the same filter" as the asset list) rather than bespoke per-page implementations. Confidence: 0.6
- Expects a data-management capability introduced for one list page to be rolled out uniformly to every comparable master/list entity — e.g. CSV export/import requested for SIM Card, Data Internet, Employee, Department, and Location (plus the existing Aset page) all at once, not one page at a time; repeated with preview-dialog navigation ("asset data dan sim card" requested together in one sentence). Confidence: 0.7
- Prefers a dedicated main Dashboard as the app landing page (root route redirects to it), with summary/recap statistics consolidated there rather than on the list pages. Confidence: 0.5
- Expects role-based access control to be reflected in the UI, not just enforced at the route/middleware level: navigation menus must hide entries a role cannot access (e.g. BAST menu removed for the guest role) instead of relying only on route redirects. Also treats guest as a read-only role by default: new features are fine to expose to guests for viewing, while create/edit/delete stays admin-only (hidden action buttons, guest write API calls rejected with 403, admin-only pages redirect instead of erroring). Confidence: 0.55
- Decorative image/illustration flourishes in the UI are tentative, not settled taste — the monochrome pixel-art dashboard art was rejected outright ("tidak sesuai ekspetasi, jelek"), and later the login page's decorative side-image panel was removed at their request ("hapus gambar yang sebelumnya dipakai", "ubah ke bentuk sederhana saja"). When they say "sederhana saja", favor stripping decorative imagery down to a simple, minimal layout (e.g. a single centered form column) rather than a split-screen with an image panel. Confidence: 0.4
- Prefers conventional, immediately-recognizable icons for navigation entries — e.g. a gear/cog for "Settings" rather than a more literal but less standard glyph (a database cylinder). Confidence: 0.35
- Prefers simple numeric-only business identifiers (plain digits, e.g. `1001`) over formatted alphanumeric codes with letters/prefixes (e.g. `INT-2026-001`), and expects the input to restrict typing to digits. Confidence: 0.5
- Creates technical documentation (e.g. internet topology diagrams) with app.diagrams.net / draw.io, and expects documentation features to accommodate that workflow (e.g. letting them insert an exported draw.io diagram as an image in a document) rather than replacing draw.io with an in-app editor. Confidence: 0.5
- Prefers documentation to live as in-app Markdown content (written and edited inside the app, admin writes / guest reads) rather than as an archive of uploaded files or an embedded third-party editor. Confidence: 0.4
- Prefers shadcn-ui as the standard UI component library over custom/hand-rolled markup and styling. Confidence: 0.6
- Prefers a single consolidated Export button with a dropdown offering PDF/CSV format choices over separate side-by-side Export PDF and Export CSV buttons. Confidence: 0.7
- Cares about pixel-level visual precision in the UI: expects media elements (active photo, thumbnails) to have fixed, uniform dimensions/proportions, complete/readable labels (no truncated text), and no cramped or overflowing layout — explicitly asks for sizes to be "presisi" while "tidak merusak tampilan UI". Confidence: 0.35
- Expects the app to let users recover from their own mistakes (e.g. a wrong image upload) with a non-destructive, reversible action — favors a "make this older file active again" swap (the mistaken file moves into history, nothing is lost) over delete-only flows, and asks about this kind of correction path unprompted. Confidence: 0.4
- Prefers secondary/advanced content tucked behind a dedicated button that opens its own dialog, rather than embedded as extra sections, strips, or lists inside the primary view — the main preview should stay simple ("tambahkan saja tombol untuk mengakses data history"). Confidence: 0.5
- Wants an existing element to be reverted exactly to its original size/look when a change deviates from it ("kembalikan ke ukuran lama"), with new capability added as an additive control instead of restructuring the original layout. Confidence: 0.5
- Wants file/history data bounded to a small fixed window of recent versions (e.g. the last 5 months of photo history) rather than an unlimited archive. Confidence: 0.4
- Wants the app's version number visible in the UI so they can tell which version is running — displayed as small/subtle text directly below the app title. Confidence: 0.5
- Prefers exported tables/files to carry concise values: hierarchical department paths are written as just the leaf/last segment (e.g. "Network" instead of "IT > Infrastructure > Network") in exports — explicitly asked "jangan tulis secara lengkap. department terakhirnya saja" — and expects the fix applied consistently across all exports (CSV & PDF, assets and employees). Confidence: 0.8
- Wants app branding/title changes applied consistently across every surface where the name appears: when renaming the app title they explicitly include both the login form heading and the dashboard sidebar in the same request ("ganti juga pada halaman dashboard"), so one unified name ("IT Helpdesk Asset Management") shows everywhere instead of being updated in only one place. Confidence: 0.4
- Prefers auth/form UI to read as substantial on a real laptop screen, not a small box floating in the middle: when the simple centered login card felt "kecil ditengah", they handed over https://sumopod.com/login as the size benchmark and asked for added wording to make the size "pas" — accepted result: wider card (max-w-md with roomier ~32px inner spacing), larger centered bold title (text-2xl), a supporting description line, and a small help-text footer. The layout stays simple/minimal (consistent with their "sederhana saja" taste), but proportions and copy should fill the screen generously; they are comfortable with the agent inventing that supporting copy itself. Confidence: 0.7
- Wants to flip through records directly inside a preview dialog via prev/next arrow buttons rather than closing and reopening each row: chevron icon buttons in the dialog header that step through the records of the current list/section in table order, with a small "n / total" position indicator and arrows disabled at the boundaries — requested for both the asset data and SIM card previews in one ask. Confidence: 0.45
