# Workflow

- Prefers incremental, staged delivery: asks to build the UI layer first (with mock data) before wiring up backend/database work. Confidence: 0.5
- Wants changes verified "live": asks for the app to be started on a dev server (e.g., localhost:3000) and left running so they can click through and test in the browser, not just via automated checks — directly instructs the agent to launch it ("coba run dev"). Confidence: 0.6
- Runs commands in Windows PowerShell as the default terminal and expects commands typed in their natural form to work there (`npm run dev`, not `npm.cmd run dev` or switching to another shell). Confidence: 0.6
- Prefers the least invasive, reversible fix for environment/system problems: chose `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` (no admin, LocalMachine untouched, reversible to Undefined) over changes that require elevated/system-wide scope. Confidence: 0.5
- When they reject a result ("hapus saja"), expects a complete removal, not a disable-and-leave-it: the artifact/files are deleted and every reference (imports, CSS variables, keyframes, call sites) is stripped so the tree returns to its exact pre-change state — verified as identical to the last commit rather than merely "close", and re-checked with grep + typecheck + lint. Confidence: 0.5
- Prefers delegating git operations to the agent — asks it to perform the actual `git commit` and `git push` rather than running the commands themselves. Responds "lanjutkan"/"continue" to authorize the agent to carry the commit+push through to completion. Confidence: 0.65
- Ships each piece of feature work on its own new feature branch (e.g. `feat/wiki-dokumentasi`) pushed to origin with `-u`, rather than committing to/master staying on the main branch — asks the agent to "push ke branch baru" and doesn't want the work merged into master behind their back. Confidence: 0.55
- Expects a commit/PR to contain only the requested feature: unrelated generated tooling files (e.g. `.commandcode/taste/*`) and pre-existing untracked assets are left in the working tree and called out, rather than swept in with `git add -A`. Confidence: 0.45
- Expects npm scripts (esp. `npm run dev`) to work directly from the repository root, without having to `cd` into a nested project subfolder — wants a permanent fix (e.g. a thin root `package.json` that delegates to the subproject) rather than a one-off workaround. Treats this as a durable constraint: the root `package.json` must be kept in place, with `dev`/`build`/`start`/`lint` continuing to delegate via `npm --prefix <subfolder> run <script>`. Confidence: 0.85
- Comfortable with the agent seeding demo/sample data into the dev database (via a re-runnable add/`--remove` script) so a new feature is immediately visible for click-through testing, rather than only being described. Confidence: 0.35
- Prefers delegating production deployment/migration execution to the agent via SSH remote access — offers to prepare SSH to the server so the agent runs the deploy steps directly, rather than just receiving a written guide to follow themselves. Confidence: 0.6
